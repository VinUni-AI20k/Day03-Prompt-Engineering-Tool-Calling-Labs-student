## 3. Đóng góp cụ thể

### 3.1. Xây dựng giao diện Live Chat cho Research Agent

- Xây dựng `app.py` bằng Streamlit, tạo giao diện chat để người dùng tương tác trực tiếp với Research Agent thay vì phải sử dụng terminal.
- Xây dựng `chat_service.py` với class `ChatSession`, đóng vai trò trung gian giữa UI và Agent Engine. Class này khởi tạo provider, load system prompt, tool declarations, quản lý conversation history và lưu transcript.
- Tích hợp `app.py` với `ChatSession` để gửi câu hỏi đến `run_model_tool_loop()` trong `chat.py` và nhận kết quả trả về.
- Sử dụng `st.session_state` để duy trì lịch sử hội thoại và session của người dùng qua các lần Streamlit rerun. Mỗi session có `ChatSession` và transcript riêng, tránh dùng chung history giữa các cuộc hội thoại.
- Bổ sung chức năng tạo conversation mới, trạng thái loading bằng `st.spinner`, hiển thị lỗi bằng `st.error` và thông tin trạng thái sau mỗi lượt xử lý.
- Bổ sung khu vực hiển thị `tool_events` để kiểm tra Agent đã gọi tool nào và kết quả thực thi.
- Hiển thị thông tin transcript ID và đường dẫn lưu transcript để thuận tiện kiểm tra, đối chiếu khi demo.

### 3.2. Tích hợp và kiểm thử khả năng tương thích với Agent

- Kiểm tra luồng hoạt động từ Streamlit UI → `ChatSession` → `run_model_tool_loop()` → Provider/Tools → câu trả lời trả về UI.
- Kiểm thử Live Chat bằng OpenRouter với các câu hỏi thực tế, bao gồm câu hỏi thông thường và câu hỏi cần Agent sử dụng tool.
- Kiểm tra khả năng hiển thị câu trả lời Markdown và đề xuất sử dụng cú pháp LaTeX chuẩn để trình bày công thức toán học.
- Kiểm tra sự đồng nhất giữa Agent version hiển thị trên UI, version được truyền vào `ChatSession` và metadata trong transcript. Phát hiện vấn đề khi version được cố định là `v0` trong khi prompt và tools trên máy đã được cập nhật lên phiên bản mới hơn.
- Kiểm tra dependency của UI và bổ sung Streamlit vào `requirements.txt` để những thành viên khác có thể cài đặt và chạy giao diện trong môi trường riêng.
- Thiết kế theo hướng UI không phụ thuộc vào tên tool cụ thể: khi backend đăng ký thêm tool mới như `github_search`, UI vẫn có thể nhận và hiển thị thông tin thực thi thông qua `tool_events` mà không cần viết lại phần chat.

### 3.3. Bonus — Gửi tin nhắn thật lên Telegram

- Tích hợp `telegram_service.py` (hoặc module xử lý API của Telegram) sử dụng Bot Token và Chat ID thực tế để kết nối trực tiếp với hệ thống nhắn tin.
- Cấu hình cơ chế kiểm tra điều kiện xác nhận bảo mật (`confirmed=true`) sau khi người dùng đồng ý qua luồng `clarify` (response_type="yes_no"), ngăn chặn tuyệt đối tình trạng Agent tự động gửi tin nhắn rác mà chưa có sự cho phép.
- Đảm bảo khi nhận lệnh gửi từ Agent, nội dung tin nhắn được truyền chuẩn xác qua API Telegram.
- Thực thi chạy thử nghiệm gửi bản tin thực tế lên kênh/chat Telegram của nhóm và lưu trữ transcript chứng minh tin nhắn đã được gửi thành công.

### 3.4. Bonus — Small Local Model Challenge

- Sử dụng provider **Ollama** chạy cục bộ trên máy cá nhân với các local model: `qwen2.5:7b` và `llama3.2:3b`.
- Xây dựng file cấu hình riêng (`system_prompt_local.md` và `tools_local.yaml`) được tối ưu hóa rút gọn, bổ sung few-shot examples để phù hợp với giới hạn ngữ cảnh và khả năng suy luận của model nhỏ.
- Thực hiện chạy thử nghiệm đánh giá qua bộ test (`eval_base.json` và tập thu nhỏ `eval_mini.json`), ghi nhận log thực tế vào hệ thống (`version_log.csv` đến phiên bản `v5`).
- Kết quả đánh giá: 
  - Khắc phục thành công hiện tượng treo/hang vô hạn ở các ranh giới bảo mật phức tạp (như `R12_confirm_before_send`) bằng cách đưa quy tắc ép buộc gọi `clarify` lên đầu prompt.
  - Phân tích và làm rõ những hạn chế đặc trưng của model nhỏ (như lỗi `wrong_tool` ở các tác vụ routing phức tạp so với model Cloud cao cấp).
